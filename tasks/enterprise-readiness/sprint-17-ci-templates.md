## New templates

### `go/internal/initcmd/templates/gitlab-ci.yml`

```yaml
# Fendix security scan — GitLab CI
#
# Generated by `fendix init --ci gitlab`.
# Produces a GitLab SAST report uploaded as a CI artifact.

fendix-security-scan:
  stage: test
  image: alpine:latest
  variables:
    FENDIX_VERSION: "v0.14.0"  # pin to a tagged release
  before_script:
    - apk add --no-cache curl ca-certificates
    - curl -fsSL "https://github.com/Abdel-RahmanSaied/Fendix/releases/download/${FENDIX_VERSION}/fendix-linux-amd64.tar.gz" | tar xz -C /usr/local/bin
    - chmod +x /usr/local/bin/fendix
  script:
    - fendix scan --code . --format sarif --output gl-sast-report.json --fail-on HIGH
  artifacts:
    when: always
    reports:
      sast: gl-sast-report.json
    paths:
      - gl-sast-report.json
    expire_in: 30 days
  allow_failure: false
```

### `go/internal/initcmd/templates/circleci-config.yml`

```yaml
# Fendix security scan — CircleCI
# Generated by `fendix init --ci circleci`.

version: 2.1

jobs:
  fendix-scan:
    docker:
      - image: cimg/base:current
    steps:
      - checkout
      - run:
          name: Install Fendix
          command: |
            FENDIX_VERSION="v0.14.0"
            curl -fsSL "https://github.com/Abdel-RahmanSaied/Fendix/releases/download/${FENDIX_VERSION}/fendix-linux-amd64.tar.gz" | sudo tar xz -C /usr/local/bin
      - run:
          name: Run Fendix scan
          command: fendix scan --code . --format sarif --output fendix-report.json --fail-on HIGH
      - store_artifacts:
          path: fendix-report.json

workflows:
  security:
    jobs:
      - fendix-scan
```

## CLI flag

```
fendix init [--ci github|gitlab|circleci]
```

Auto-detect default:
- If `.github/` exists → `github`
- Else if `.gitlab-ci.yml` exists → `gitlab`
- Else if `.circleci/` exists → `circleci`
- Else → `github` (most common)

## File paths emitted

| `--ci` | Path |
|---|---|
| `github` | `.github/workflows/fendix.yml` (current behaviour) |
| `gitlab` | `.gitlab-ci.fendix.yml` (a separate file the user `include:`s from their main `.gitlab-ci.yml`) |
| `circleci` | `.circleci/fendix-config.yml` (orb-style snippet the user merges into their main config) |

For gitlab/circleci, also emit a `NEXT-STEPS.md` explaining how to wire the snippet into the user's main CI config (since CircleCI and GitLab don't merge multiple config files automatically the way GH Actions does).

## Update detect.go

```go
type DetectionResult struct {
    ProjectType string  // existing
    CIType      string  // NEW: "github" | "gitlab" | "circleci" | "" (unknown)
}

func DetectCI(rootPath string) string {
    if exists(filepath.Join(rootPath, ".github")) { return "github" }
    if exists(filepath.Join(rootPath, ".gitlab-ci.yml")) { return "gitlab" }
    if exists(filepath.Join(rootPath, ".circleci")) { return "circleci" }
    return ""
}
```

## Risks

- **GitLab SAST report schema changes occasionally.** Pin the schema version in the template's `# generated against schema X.Y` comment.
- **CircleCI orb vs. inline config.** This sprint uses inline; an orb would be cleaner but requires CircleCI's orb-publication process.

## Definition of done

Standard DoD plus:
- Each emitted YAML parses cleanly with `gopkg.in/yaml.v3`
- `fendix init --ci gitlab` against a fresh repo produces output that GitLab CI's syntax validator accepts (manual verify)
- README mentions multi-CI support
