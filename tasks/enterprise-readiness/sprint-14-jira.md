## Why

Enterprise security teams live in Jira. "Findings appear in a JSON report" is invisible to them. This sprint syncs CRITICAL+HIGH findings to Jira as Bug issues, idempotently, with auto-resolution when fixed.

**Prerequisite:** Sprint 07 (`fendix serve`) must ship first — this runs as a post-scan hook in serve mode.

## Config

```yaml
integrations:
  jira:
    url: ""              # e.g. https://your-org.atlassian.net
    project_key: ""      # e.g. SEC
    api_token: ""        # Jira API token
    email: ""            # Jira account email
    min_severity: HIGH   # create tickets for CRITICAL and HIGH only
    issue_type: Bug      # default; some projects use "Task" or "Vulnerability"
    rate_limit_qps: 5    # tokens-per-second to the Jira API
```

Auth: Basic, `Authorization: Basic base64(email:api_token)`.

## Idempotency

Each Jira issue gets a label `fendix-id:<finding.ID>`. Before creating:
1. JQL: `project = {key} AND labels = "fendix-id:{id}"`
2. If found, skip create (idempotent)
3. If found AND finding is resolved (not in latest scan), transition to Done

## API surface

```go
package jira

type Client struct {
    baseURL string
    email   string
    token   string
    project string
    httpc   *http.Client
    limiter *rate.Limiter // golang.org/x/time/rate — NEW INDIRECT, may be available via OAuth2 transitive; confirm before adding
}

// SyncFindings is the entry point. Idempotent:
//   - For each finding ≥ min_severity: ensure a Jira issue exists with
//     label fendix-id:<id>
//   - For each existing issue with that label whose finding ID is NOT
//     in the current scan: transition to Done
func (c *Client) SyncFindings(ctx context.Context, findings []models.Finding, jobID string, minSeverity models.Severity) (SyncResult, error)

type SyncResult struct {
    Created   []string // Jira issue keys
    Reopened  []string
    Resolved  []string
    Unchanged []string
    Errors    []SyncError
}
```

## Rate limiting

Jira Cloud free tier: 10 req/s; paid tiers higher. Default to 5 req/s using a token bucket (`golang.org/x/time/rate` — confirm available or use a hand-rolled bucket).

## Transition discovery

To transition an issue to "Done", you need the transition ID, not the name. Per issue:
1. `GET /rest/api/3/issue/{key}/transitions`
2. Find transition with name `"Done"` (or `"Resolved"`, configurable via `resolve_transition_name` config)
3. `POST /rest/api/3/issue/{key}/transitions` with `{"transition": {"id": "<id>"}}`

Cache transition IDs per project — they're stable.

## Risks

| Risk | Severity | Mitigation |
|---|---|---|
| Jira's JQL label escaping quirks across versions | Med | Test against Jira Cloud + Server 9+; document supported versions. |
| Closed issue re-detected — reopen or new? | Decision needed | **Default: reopen** the closed issue with a comment "fendix re-detected this on {date}". Configurable via `reopen_resolved: true|false`. |
| Project doesn't have a "Done" transition (uses "Resolved", "Closed", etc.) | Med | `resolve_transition_name` config; default "Done"; fall back to the first terminal transition if not found, log a warning. |
| Customer's `description` field is configured to require ADF (Atlassian Document Format), not plain text | Med | Detect on first create failure; auto-wrap in ADF if needed. ~30 LOC of fallback. |
| Per-finding sync is N requests; large scans slow | Low | 5 req/s × 100 findings = 20s. Acceptable; document. |
