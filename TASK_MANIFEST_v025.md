## Governing principle (roadmap)
"Make using Fendix faster and less frustrating. **Measure it. Ship only what
moves the metric.**" DX is adoption — ignored findings = no security improvement.

## Honest scoping note (the measurement reality)
- **time-to-triage is a HUMAN metric** the tool can't self-measure in CI. The
  realistic v0.25 deliverable is (a) the DX improvements that plausibly reduce
  it, plus (b) the INSTRUMENTATION (extend the v0.20 `FENDIX_METRICS` collector)
  to measure CLI-success-rate + proxies — with the ≥30% validated over real
  usage, exactly like the v0.20 baseline was. Don't claim a measured 30% from a
  code change alone.
- Some DX changes alter CLI/report output. Handle deliberately: the v0.20
  output snapshots project only `category|severity|title` (additive output is
  safe); JSON schema changes go in lockstep with `schema.json` (the byte-gate).

## Roadmap deliverables (refined to a measurable shortlist after the blueprint)
- Improved CLI UX — better error messages, progress feedback.
- Faster incremental scans (changed files only) — build on `--diff`/`--staged`/`--fast`.
- Better PR comment formatting — lead with decisions (build on v0.24).
- Improved pre-commit workflow.
- Developer onboarding improvements.
- Instrumentation: CLI success rate (and a time-to-triage proxy) via the metrics collector.

## Won't Do (roadmap)
- Chatbot, web dashboard, mobile app. Ship only what moves the metric.
