## 3. SAST Engine

The white-box surface is **multi-engine**: native Go regex secrets, a Go wrapper around the host `semgrep` binary, and an optional Python AST analyzer that must be opted into with `--python-engine`.

### 3.1 Native secrets scanner — [go/internal/scanner/secrets/scanner.go](go/internal/scanner/secrets/scanner.go) (498 lines)

- **Technique:** Go `regexp` (RE2). Because RE2 lacks lookarounds, the Python lookbehinds/lookaheads have been stripped and replaced with manual boundary-char checks via the `leftBoundary` / `rightBoundary` regex fields ([scanner.go:69-99](go/internal/scanner/secrets/scanner.go#L69-L99)).
- **Pipeline:** `Scan(ctx, codePath)` → `filepath.WalkDir` → skip-dir prune → extension gate → per-line pattern match → boundary check → emit `models.Finding` with ID `SEC-<PATTERN_ID>`.
- **File caps:** 1 MB max ([scanner.go:41](go/internal/scanner/secrets/scanner.go#L41)); skip lines >500 chars in `.js/.ts` ([scanner.go:45](go/internal/scanner/secrets/scanner.go#L45)); evidence truncated to 120 chars; secret value shown as first 20 chars + `...` ([scanner.go:43-47](go/internal/scanner/secrets/scanner.go#L43-L47)).
- **Skip dirs:** `.git`, `node_modules`, `vendor`, `__pycache__`, `.venv`, `venv`, `dist`, `build`, `.tox` ([scanner.go:54-57](go/internal/scanner/secrets/scanner.go#L54-L57)).

### 3.2 Semgrep wrapper — [go/internal/scanner/semgrep/scanner.go](go/internal/scanner/semgrep/scanner.go) (433 lines)

- **Technique:** Shells out to the host `semgrep` binary; rules are YAML files embedded into the Go binary via `go:embed` from `go/internal/scanner/semgrep/rules/`.
- **Invocation:** `exec.CommandContext(ctx, "semgrep", "--config", rulesDir, "--json", "--no-git-ignore", codePath)`.
- **Graceful absence:** Returns `ErrSemgrepUnavailable` when binary is missing; orchestrator logs `"semgrep not installed — skipping (install with: pip install semgrep)"` and continues ([orchestrator.go:296-297](go/internal/engine/orchestrator.go#L296-L297)).
- **Rule packs:** `rules/secrets.yaml`, `rules/injection.yaml`, `rules/auth.yaml`. Total embedded rules: **6** (2 secrets, 3 injection, 1 auth).

Example rule from `rules/secrets.yaml`:

```yaml
- id: python-hardcoded-secret-assignment

    - metavariable-regex:
```

### 3.3 Python engine (opt-in)

- **Activation:** `--python-engine` flag ([main.go:345](go/cmd/fendix/main.go#L345)).
- **Behavior:** Go shells out to `python3` via `engine/spawner.go` (NewPythonSpawner). NDJSON IPC contract — Go writes a ScanRequest to stdin; Python emits newline-delimited Finding JSON on stdout, terminated by `{"done": true, "total": N}`.
- **Resolution:** [orchestrator.go:46-62](go/internal/engine/orchestrator.go#L46-L62) — `EnsureEngine` looks for a local `python/` tree or `FENDIX_ENGINE` env var. **The embedded Python distribution was dropped in TASK-118; only the source tree is shipped.**
- **What it adds (when on):** Auth / injection / deps checks via Python AST analyzers in `python/analyzers/`. With it OFF, secrets + semgrep run natively in Go and dep-CVE runs via native scanners (TASK-115, TASK-116, TASK-119).

## 4. Dependency CVE Scanner

- **Location:** `go/internal/scanner/deps/` with sub-packages `pip/`, `npm/`, `govulncheck/`.
- **External tool / library use:**
  - **Python (pip):** OSV.dev REST API queries — no `pip-audit` subprocess; the file header explicitly notes "behavioural parity with pip-audit" but the implementation is a direct OSV API client.
  - **npm:** OSV.dev REST API; parses `package-lock.json` v2/v3 for resolved versions.
  - **Go:** `golang.org/x/vuln` (library, not the `govulncheck` binary) — call-graph reachability included.
- **CVE data source:** [OSV.dev](https://osv.dev) `/v1/query`. Endpoint: `https://api.osv.dev` (overridable via `osvAPIBase` for tests) — [pip/scanner.go:79](go/internal/scanner/deps/pip/scanner.go#L79).
- **Caching:** `~/.fendix/cache/osv-pypi/<package>@<version>.json` with a 24h TTL ([pip/scanner.go:22-24, 83](go/internal/scanner/deps/pip/scanner.go#L22-L24)). HTTP timeout per request: 15 s ([pip/scanner.go:88](go/internal/scanner/deps/pip/scanner.go#L88)).
- **Manifests supported:**
  - Python: `requirements.txt` only (no `pyproject.toml` / `setup.py` / `Pipfile` introspection).
  - npm: `package-lock.json` v2/v3. With `package.json` present but no lock file, the orchestrator emits an advisory `SEC-NPM_LOCKFILE_MISSING` INFO finding ([orchestrator.go:243-258](go/internal/engine/orchestrator.go#L243-L258)).
  - Go: `go.mod` (via `golang.org/x/vuln`).
- **Recursion:** Yes for Python via `pip.ScanRecursive` (depth ≤ `DefaultRecurseDepth = 3`). Proof — [pip/scanner.go:161-208](go/internal/scanner/deps/pip/scanner.go#L161-L208):

```go
func ScanRecursive(ctx context.Context, codePath string, maxDepth int) ([]models.Finding, error) {
    // ...
    manifests, err := findRequirementsManifests(abs, maxDepth)
    // ...
    for _, m := range manifests {
        content, err := os.ReadFile(m)
        // ...
        pkgs := parseRequirements(string(content))
        // ...
        for _, p := range pkgs {
            vulns, qerr := queryOSV(ctx, client, cache, p.name, p.version)
            // ...
            for _, v := range vulns {

            }
        }
    }
    sortFindingsByID(all)
    return all, nil

```

## 5. DAST Engine

- **Location:** `go/internal/scanner/` — one file per check.
- **HTTP client:** Standard library `net/http.Client` with a wrapped transport from `internal/budget.Transport()` that enforces `--max-requests` and per-scan counters. Example wiring — [auth.go:28-34](go/internal/scanner/auth.go#L28-L34):

```go
client := &http.Client{
    Timeout:   time.Duration(cfg.Timeout) * time.Second,
    Transport: budget.Transport(),
    CheckRedirect: func(req *http.Request, via []*http.Request) error {
        return http.ErrUseLastResponse
    },

```

- **Crawler:** `go/internal/scanner/crawler.go` (1,407 lines). Entry: `NewCrawler(cfg).CrawlEndpoints(ctx)`. `--crawl-depth` (default `1`) governs recursive HTML link following from the start URL — `0` disables link following, `1` only follows links from the home page, `>1` recurses further (same-host only). `--max-endpoints` (default `500`) caps the total queue. `--wordlist` overrides built-in `CommonPaths`. `--respect-robots` toggles whether `robots.txt` `Disallow` is a hard restriction or queued as a discovery hint.

### JWT auth probes — [go/internal/scanner/auth.go](go/internal/scanner/auth.go)

`CheckAuth` orchestrates four probes:

1. **Missing auth** — `checkUnauthenticated(...)` ([auth.go:39](go/internal/scanner/auth.go#L39)): re-issues the original request with the Authorization header stripped; 2xx → CRITICAL "Missing authentication".
2. **Malformed JWT** — `checkJWTBypasses(...)`: sends `Authorization: Bearer <not-a-jwt>`.
3. **Expired JWT** — same helper: synthesises a JWT with `exp` set in the past (HS256, custom key the server doesn't share) and inspects the response.
4. **alg:none** — same helper: synthesises a JWT with header `{"alg":"none","typ":"JWT"}` and an empty signature.

The HMAC machinery (`crypto/hmac`, `crypto/sha256`, `encoding/base64`) imported at the top of `auth.go` ([auth.go:3-13](go/internal/scanner/auth.go#L3-L13)) is what builds the bypass JWTs.

#### FP-dedup for JWT bypass probes — [auth.go:44-99](go/internal/scanner/auth.go#L44-L99)

```go
// FP-dedup (Track 4 gap surfaced by TwiScope-backend /metrics scan).
//
// When the endpoint accepts a request with NO Authorization header
// AND also accepts a request with a syntactically-invalid header
// (e.g. "Bearer junk"), the auth handler isn't checking auth at
// all — every JWT-bypass probe (malformed / expired / alg:none)
// will also return 200, but those findings are downstream byproducts
// of the same root cause.
suppressJWTProbes := false
if missingAuth != nil && isJWTAuth(cfg.Auth) {
    if endpointAcceptsGarbageAuth(ctx, client, endpoint) {
        suppressJWTProbes = true
        slog.Debug("auth check: suppressing JWT-bypass probes …", "endpoint", epLabel)
    }
}

if isJWTAuth(cfg.Auth) && !suppressJWTProbes {
    findings = append(findings, checkJWTBypasses(ctx, client, cfg, endpoint, epLabel)...)
}
```

`endpointAcceptsGarbageAuth` sends `Authorization: Bearer fendix-auth-probe-not-a-real-token` and returns `true` only on a 2xx ([auth.go:87-99](go/internal/scanner/auth.go#L87-L99)). Network errors return `false` (conservative — keeps the probe in play).

### Severity decisioning

Severity is **hardcoded per check** rather than computed dynamically. Each check function returns Findings with the appropriate `models.Severity` constant. Examples:
- `CheckAuth → missing auth → SeverityCritical`
- `CheckHeaders → missing CSP → SeverityHigh`
- `CheckCORS → wildcard origin → SeverityMedium`
- `CheckRateLimit → no rate-limit headers → SeverityMedium`

There is no scoring matrix file; the severity assignments live inline in each check file.

### FP/dedup at scan-wide level

DAST findings flow into the same `Deduplicate` step described in §3.4 ([dedup.go](go/internal/engine/dedup.go)), so e.g. "missing CSP × 21 endpoints" collapses into one finding with 21 `AffectedEndpoints`. The auth-specific suppression above is in addition to that — it prevents the duplicates from being emitted in the first place.

```go
func Run(ctx context.Context, findingID string, opts Options) (*Result, error) {
    start := time.Now()
    out := &Result{
        FindingID:  findingID,
        VerifiedAt: start.UTC().Format(time.RFC3339),
    }

    baseline, err := loadBaseline(opts.BaselinePath)
    if err != nil {
        return nil, fmt.Errorf("verify: load baseline: %w", err)
    }

    original := findByID(baseline, findingID)
    if original == nil {
        out.Status = StatusNotFound
        out.Reason = fmt.Sprintf("finding %q not present in baseline %q", findingID, opts.BaselinePath)
        out.LatencyMs = time.Since(start).Milliseconds()
        return out, nil
    }
    out.Original = original

    switch {
    case isDepFinding(original):
        verifyDep(ctx, original, opts, out)
    case isURLFinding(original):
        verifyURL(ctx, original, opts, out)
    case isFileFinding(original):
        verifyFile(ctx, original, opts, out)
    default:
        out.Status = StatusUnknown
        out.Reason = "finding shape not yet supported by verify (correlated/active-probe paths are MVP-deferred)"
    }

    out.LatencyMs = time.Since(start).Milliseconds()
    return out, nil
}
```

## 15. Your Assessment

### 1. Three most critical claim-vs-reality gaps

1. **GitHub App webhook handler is stubbed.** The README/docs imply zero-friction CI install via a GitHub App; the runtime handler is explicitly marked stubbed at [go/internal/ghapp/webhook.go:7](go/internal/ghapp/webhook.go#L7). Practically, users must rely on the generated GitHub Actions workflow, which **does** work — but the GitHub App path is currently fictional.
2. **`pip-audit` claim vs. implementation.** Code comments and (likely) docs reference pip-audit parity; the actual implementation is a direct OSV.dev REST client ([go/internal/scanner/deps/pip/scanner.go](go/internal/scanner/deps/pip/scanner.go)). The behaviour is similar but the tool shown to users is not the tool that runs. This matters for trust and reproducibility ("did you run pip-audit?" — no).
3. **Embedded semgrep rule pack is very small.** Only 6 rules across 3 YAML files. The "deeper static analysis" framing oversells what ships out of the box; meaningful semgrep coverage still depends on the user installing semgrep *and* providing rules.

### 2. Highest-risk area for correctness

The **correlator** ([go/internal/engine/correlator.go](go/internal/engine/correlator.go), 449 lines). It does fuzzy endpoint normalization across blackbox and whitebox findings (3-tier match: exact → suffix → segment-fuzzy), and its output drives:
- `SourceCorrelated` tagging
- The double severity escalation when `Reachable=true`
- Whether a finding is build-failing under `--fail-on HIGH`

A bug here silently produces either false negatives (missed correlations → missed escalations → builds that should fail but don't) or, less dangerously, false positives. The test file is the largest in the engine package (21 `Test*` functions), which is encouraging — but the surface is large.

### 3. Cleanest reusable code

- **`internal/engine/dedup.go`** — small (157 lines), pure-function, well-doc'd, with explicit merge rules and confidence-rank semantics. Easy to extend.
- **`internal/scanner/secrets/scanner.go`** — clean pattern registry, defensible boundary semantics replacing RE2's missing lookarounds, parity comments tying it back to the Python source.
- **`internal/initcmd/`** — `go:embed` templates + a pre-flight existence check for atomic-ish writes is a good shape.

### 4. What would break first under enterprise load

- **OSV.dev rate limiting / outage.** The dep-CVE scanners hit `api.osv.dev` once per pinned package; for a monorepo with hundreds of pinned deps and a cold cache, that's a serialised wall of HTTP requests. No backoff, no concurrency cap, no batching visible in [pip/scanner.go](go/internal/scanner/deps/pip/scanner.go). An OSV.dev rate-limit or outage will fail or stall scans even though every other engine is healthy.
- **Crawler memory.** Endpoints are accumulated into a slice before checks run; `--max-endpoints` defaults to 500 but a misconfigured large-scope scan could push memory hard. The check itself is not the issue — the all-at-once buffer between discovery and check execution is.
- **Semgrep subprocess timeout.** Default in code is 120s per invocation (per the prior auditor's reading); no chunked invocation across very large code trees.

### 5. Single most important fix before external evaluation

**Document the OSV.dev dependency and the `pip-audit`-naming gap, OR rename the implementation to be honest about what it does.** Right now the docs/comments mention pip-audit parity but the implementation is an OSV.dev client. An external evaluator will run a scan, read the docs, and conclude that the tool's self-description doesn't match its behaviour — which damages trust more than any individual missing feature. Two viable fixes:

1. Rewrite the dep-CVE doc/code to say "OSV.dev /v1/query client" explicitly.
2. Add a fallback path that invokes `pip-audit` when present, so the parity claim is operative.

Either path is a few hours of work. The current ambiguity is the highest-leverage fix because it changes how the next evaluator scores the entire project.
