## The constraint that shaped this version (read first)
The pre-v1.1 blocker was **performance, not detection**: a full `--python-engine`
scan of the TWISCOPE seed repo (~1,188 Python files) took **~50 min** because
`ASTAnalyzer._expr_references_secret` re-walked bound subtrees combinatorially.
Without that fixed, no real precision number could exist (Rule 5: a number you
can't reproduce in a practical window isn't a number). So Task P — a first-class
perf fix (Rule 6) — came first and unblocked everything downstream.

The second constraint was **honesty about the number**: the labels were authored
against a pre-Phase-B triage, so most FP entries now describe findings the engine
no longer emits. The measured 33.3 %-over-labeled is a thin-denominator lower
bound, disclosed as such; the defensible headline is the TP-retained / FN-zero /
FP-classes-eliminated statement, not the ratio.
