## The defining honesty constraint (read first)
A Java taint analyzer matching the Python engine's depth is a **very large**
effort and CANNOT reach OWASP-Benchmark quality in one increment. A shallow
Java analyzer that then publishes OWASP recall/precision numbers would be
**exactly the Rule 5 violation v0.26 just removed.** Therefore:
- v0.27 ships a **real but bounded** first Java increment (the depth the
  blueprint deems honestly claimable — likely textscan Java rules + a verified
  semgrep Java path), with its own reproducible BENCHMARKS.md entry.
- **OWASP Benchmark stays a loud, documented SKIP** (`Run()` → `ErrTargetSkipped`
  so no empty/0.0 result can ever persist) until deep Java taint analysis
  exists. No OWASP number is claimed this phase. A clear "what unblocks a real
  OWASP number" note is left for a future phase.
