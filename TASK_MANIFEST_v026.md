Exit criteria: *"Honest, reproducible, published accuracy numbers. No marketing claim without a re-runnable benchmark."* (Product Constitution Rule 5)

## Governing principle
Turn Fendix's accuracy story from **assertion** into **evidence**. Every
published number (recall / precision / F1 / FP-rate) must be reproducible by a
third party: pinned corpus, documented methodology, deterministic scoring,
ideally re-checked in CI. Rule 8: AI never decides a score or a label.

## Hard constraints (the honesty that defines this phase)
- **OWASP Benchmark is Java; Fendix has no Java analyzer until v0.27.** It MUST
  keep loud-SKIPping — never publish a fake ~0-recall number from it (that is
  itself a Rule 5 violation — a misleading baseline). DAST accuracy = DVWA +
  Juice Shop (HTTP, language-agnostic); SAST accuracy = the `scripts/heavy-eval`
  Python/Go corpus.
- **No number without a reproducible source.** Any EXISTING unsubstantiated
  accuracy/marketing claim (in README/docs/comments) is a live Rule 5 violation
  → MUST be backed by a real number or removed/softened.
- **Scan-report JSON schema stays stable.** Output may grow a `BENCHMARKS.md` +
  README numbers; the v0.20 snapshots (project category|severity|title) stay
  green; any JSON change is additive + schema-lockstep.
