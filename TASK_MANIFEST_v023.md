Generated by: Orchestrator Agent

Exit criteria: *"Every security decision comes with a confidence score and a plain-text reason. No black boxes. No AI in the scoring path."*

## Governing invariants
- **No AI in the scoring path** (Constitution Rule 8) — deterministic, rule-based, auditable.
- **Internal only in v0.23** — roadmap "Won't Do" forbids a user-facing confidence UI; CLI output stays byte-identical (guarded by `tests/regression/output_format` snapshots + `reporters/schema_test.go`). The score feeds v0.24's decision reports.

## Existing machinery (do NOT rewrite — Rule 1)
- `models.Confidence` enum HIGH/MEDIUM/LOW + `ConfidenceMult` (1.0/0.75/0.5), used in `CalculateSeverity` (Score = Base × ConfidenceMult × SourceMult).
- `MaxSeverityForConfidence` + `EnforceSeverityConsistency` cap severity by confidence.
- Correlator sets the enum (Medium for unmatched whitebox, High for correlated); orchestrator runs `enforceConsistency`.
- `decision.Decision.Confidence` currently just copies `ev.Confidence` (the enum).
- **v0.22 already threads the inputs** the scorer needs onto `evidence.Evidence`: `Source` (cross-engine agreement), `RouteConfirmed` (runtime confirmation), `Reachable` + `TaintChain` (reachability), `ProvenPath`, `SourceTier`, `Payload`/`Response` (payload validation), `Lineage` (evidence chain).

## Genuinely new (the v0.23 work)
- **`internal/confidence`**: a deterministic `Score(evidence.Evidence) Result{Value 0–100, Band, Reasons []string}`. Each roadmap input (static evidence, runtime confirmation, auth context, endpoint reachability, payload validation, cross-engine agreement, source tier) contributes a fixed, documented delta and a plain-text reason. Pure function, no AI, no I/O.
- **Evidence-chain tracing**: render `ev.Lineage` (the BB+WB inputs that merged) into the reasons so a correlated score is traceable.
- **Wire into `decision.Decision`** (add `Score confidence.Result`), computed in `Decide`. INTERNAL — not serialized; existing `Confidence` enum + severity + output unchanged.
- Confidence unit tests + benchmark; validate the scorer changes NO output vs the v0.20 baseline.

## Design decision (taken, per roadmap)
**Purely-internal additive scorer.** The numeric score + reasons attach to the
internal Decision; the existing `models.Confidence` enum, severity computation,
and public JSON/SARIF/HTML are left untouched. (The alternative — letting the
numeric score refine the enum — would change output, which v0.23 forbids; defer
any output surfacing to v0.24.)
