## The honesty constraint that shapes this version (read first)
The roadmap's headline next item is a **deep Java taint analyzer**. Two hard
facts (confirmed in plan.md + the v0.27 review):
- It is **quarter-scale** ("tree-sitter port is a quarter's work on its own",
  plan.md:48) — not completable to production/OWASP quality in one session.
- It needs a **Java-parser architecture decision** (CGo tree-sitter — which
  breaks Fendix's single-static-binary identity — vs a separate engine vs
  shelling out). That is an **operator-owned** call, not a unilateral one.
- A shallow taint engine that then claims OWASP numbers is the exact Rule 5
  violation v0.26/v0.27 spent two phases removing.

So v0.28 ships a **real, bounded, reviewable** increment — expanded Java regex
SAST coverage (line-local, `TierNativeGo`, the same honest tier as v0.27) —
and explicitly **DEFERS** the deep taint engine + the parser decision + any
OWASP number to a future phase with a crisp definition-of-done.
