# Engine v1.1 — Real-World Precision & Trust (Design)

**Date:** 2026-07-07
**Status:** Approved (design), pending implementation plan
**Owner:** fendix-engine
**Constitution anchors:** Rule 3 (every finding has evidence), Rule 5 (benchmark before marketing), Rule 8 (deterministic scoring), Rule 10 (optimize for engineering time saved)

---

## 1. Problem

The v1.0 benchmark story is honest about its own limits (`BENCHMARKS.md:127-134`) but those
limits are exactly where the product's credibility lives:

- Published P/R/F1 = 1.000 numbers are on **hand-authored synthetic corpora**
  (`python/benchmark/corpus.json`, the SAST synthetic track). They gate regressions; they do
  not describe real-world behavior.
- The one real-repo measurement we have — `docs/TWISCOPE_SCAN_TRIAGE.md`, a production Django
  app — measured **precision ≈ 0.8% (1 TP / 128 FP)**. The three fix families it motivated
  (constant-URL-authority gate, receiver-type gating, psycopg2 composable recognizer,
  path-traversal trusted sources) landed in `python/analyzers/ast_analyzer.py`
  (`_url_authority_is_constant`, `_receiver_is_http_client`, `_is_psycopg_sql_composable`,
  `_CONST_PATH_DUNDERS`), **but real-repo precision has never been re-measured since**.
- The mirror measurement — `docs/SANAD_SCAN_TRIAGE.md`, an LLM/RAG app — found **0 FP but
  also 0 TP**: a pure recall gap (LLM-prompt sinks, env/config sources,
  `httpx.AsyncClient(base_url=…)` constructor SSRF).
- `docs/PYTHON_LAYER_ACCURACY_AUDIT.md` and `tasks/FP_CORPUS.md` enumerate residual FP
  classes that remain unaddressed (see §5).

**"Independence" for this release means detection quality you can depend on** — the native
engine's findings are trustworthy on real code, and we can prove it with our own instrument.
It does *not* mean removing the optional semgrep/OSV integrations (explicitly out of scope,
per product decision 2026-07-07).

## 2. Goals

1. A **real-world precision benchmark track** that produces an honest, repeatable
   precision / noise-density number on real repositories, wired into `fendix benchmark`.
2. A **re-measured post-fix baseline** for TWISCOPE-class code, published in `BENCHMARKS.md`.
3. The residual **FP classes fixed**, each fix proven by a harness delta and locked in with
   regression corpus cases. Noise reduction happens through the decision layer
   (de-escalation) wherever evidence is real — findings are suppressed outright only when
   the detection itself was wrong.
4. **Dependability additions**: the SANAD recall gaps closed with rules that carry corpus
   proof they do not manufacture FPs; `fendix verify` coverage extended.
5. Honest publication: docs updated, harness CI-gated, `NEXT_v110.md` + task manifest in
   house style.

## 3. Non-goals (v1.1)

- Java deep-taint (blocked on the tree-sitter / single-static-binary fork decision — needs
  its own design).
- Retiring semgrep / pip-audit / govulncheck shell-outs; completing the offline SCA story.
- Any CLI flag or output-format changes beyond the new benchmark subcommand surface.
- AI anywhere in scoring or labeling (Rule 8).

## 4. Phase A — the measurement instrument

### 4.1 Architecture

A new target `realworld` implementing the existing `BenchmarkTarget` interface
(`go/internal/benchmark/runner.go`), living at `go/internal/benchmark/targets/realworld.go`.
It reuses `baseline.go` storage and the `fendix benchmark run|baseline|compare` CLI — no new
top-level command.

Unlike the DVWA/Juice Shop targets (Docker DAST), a real-world entry is a **SAST corpus
repo**: a source tree at a pinned revision plus a committed labels file. The target:

1. resolves the repo (local path or `git clone --depth 1` at a pinned SHA into the bench
   cache),
2. runs `fendix scan --code <repo> --format json` via the existing scan-production path,
3. scores findings against the labels file,
4. emits `BenchmarkResult` plus a per-FP-class breakdown and a **triage report** of unlabeled
   findings (so labeling is incremental, not a prerequisite for running).

### 4.2 Corpus tiers

| Tier | Entries | Reproducible by | Purpose |
| --- | --- | --- | --- |
| **Seed** | TWISCOPE, SANAD (local paths, private) | us only | Immediate baseline from already-triaged verdicts; loud-SKIP when the path is absent (house style — never silently green) |
| **Public** | 2–3 pinned-SHA OSS Python/Go web apps | anyone | The publishable number; extends the v0.26 "reproducible by any engineer" ethos |
| **Regression** | per-FP-class negative cases in `python/benchmark/corpus.json` | CI | Every fix locked in forever with the existing `label: safe` mechanism |

Seed-tier paths come from a git-ignored `benchmarks/realworld/local.yaml`; public-tier
entries are committed manifests (`benchmarks/realworld/<name>/manifest.yaml` — repo URL,
pinned SHA, license note) with labels alongside.

Public-tier selection happens in the implementation plan against fixed criteria: real
(non-tutorial) Python or Go web application; OSI license permitting scan-and-publish;
≥5 KLOC; framework the engine models (Django/Flask/FastAPI, net/http/gin); active enough
that a pinned SHA is representative. Candidates are scanned, findings triaged, and the two
or three with the most instructive finding mix become the committed entries.

### 4.3 Label format and matching

Findings are labeled by a **stable key, not raw fingerprint**: fingerprints incorporate
evidence text, which legitimate analyzer fixes may change, silently orphaning labels.

```yaml
# benchmarks/realworld/<name>/labels.yaml
- rule: PY_SSRF                # finding rule/category id
  file: app/services/fetch.py  # repo-relative, normalized
  line: 142                    # anchor; match tolerance ±3 lines
  verdict: fp                  # tp | fp
  fp_class: constant-authority # required when verdict: fp (taxonomy in §5)
  note: "host is settings.BASE_URL, only path is tainted"
```

Scoring rules:

- Matched `tp` → TruePos; matched `fp` → FalsePos.
- **Unlabeled finding → `unknown`**: counted and listed in the triage report, *excluded* from
  precision until labeled. Prevents auto-mislabeling and makes the number defensible.
- Labeled `tp` with no matching finding → FalseNeg (recall signal where labels exist).
- Metrics per entry: precision over labeled findings, per-`fp_class` counts,
  findings-per-KLOC (noise density), unknown count, scan duration/memory (existing fields).

### 4.4 Seeding from the triage docs

One-time conversion of `docs/TWISCOPE_SCAN_TRIAGE.md` (129 verdicts, FP classes FP-1…FP-6)
and `docs/SANAD_SCAN_TRIAGE.md` into `labels.yaml`. The triage docs stay as narrative
provenance; the YAML is the machine truth.

### 4.5 First deliverable

Run the seed tier against current `main` → **the post-fix TWISCOPE precision number**. This
is the v1.1 baseline every Phase B fix compares against, committed via
`fendix benchmark baseline`.

## 5. Phase B — FP-class fixes (ranked by measured volume)

FP-class taxonomy (also the `fp_class` enum): `constant-authority`, `receiver-confusion`,
`safe-api-misread`, `const-fold-miss`, `guard-dominance`, `test-fixture`, `http-4xx-context`,
`static-asset-context`, `double-sanitize`, `heuristic-overfire`, `version-range-floor`,
`fabricated-chain`.

Candidate fixes, each merged only with (a) a harness precision delta, (b) regression corpus
cases (positive + negative), (c) zero regression on the existing 1.000-gated corpora:

| # | Fix | Where | Class |
| --- | --- | --- | --- |
| B1 | SQL-sink constant-folding (literal/constant SQL never taint-flagged) — the audit's biggest remaining lever | `ast_analyzer.py` `_is_sql_injection` | `const-fold-miss` |
| B2 | Membership-guard **dominance**: `_name_is_membership_guarded` currently fires on any `if X not in <literal>` anywhere in the function — must require the guard to dominate the sink. Accuracy bug in *both* directions (over-suppression = FNs today) | `ast_analyzer.py:~669` | `guard-dominance` |
| B3 | Test-vs-prod awareness: classify `**/tests/**`, `conftest.py`, `*_test.go`, `spec/**` etc.; **de-escalate via decision layer to INFO** (evidence preserved, Rule 3), config-overridable | new path classifier + `go/internal/decision` | `test-fixture` |
| B4 | DAST context de-escalation: header/CORS findings on 4xx responses; rate-limit findings on static assets — confidence deltas, not suppression | `go/internal/confidence/confidence.go` + scanners | `http-4xx-context`, `static-asset-context` |
| B5 | `Markup(html.escape(x))` double-wrap XSS FP | `ast_analyzer.py` escape tracking | `double-sanitize` |
| B6 | Weak-crypto password heuristic over-fire (`md5(x.encode())` on non-credential names) | `ast_analyzer.py` `PY_WEAK_CRYPTO_PASSWORD` | `heuristic-overfire` |
| B7 | `webbrowser.open` / non-filesystem `.open()` fabricated path-traversal chains | `ast_analyzer.py` sink typing | `fabricated-chain` |
| B8 | npm caret/tilde ranges flagged at range floor without lockfile resolution | `go/internal/scanner/deps/npm` | `version-range-floor` |

Ordering within Phase B is decided **by the Phase A per-class counts**, not by this table.

## 6. Phase C — dependability additions

Recall additions from `SANAD_SCAN_TRIAGE.md`, each landing with positive *and* negative
corpus cases (the SANAD doc's own warning: no speculative rules that manufacture FPs):

- C1: LLM-prompt-injection sink expansion (`PY_LLM_PROMPT_INJECTION` coverage for the
  patterns SANAD actually uses).
- C2: env/config-derived source modeling — narrowly scoped (request-influenced config only);
  raw `os.getenv` stays trusted (it is a fix from FP-4, do not regress it).
- C3: `httpx.AsyncClient(base_url=…)` / client-constructor SSRF modeling.
- C4: `fendix verify` coverage for **correlated** and **active-probe** findings (today both
  return `unknown`, `go/internal/verifycmd/verifycmd.go`) — verification is the product's
  strongest trust primitive.

## 7. Phase D — honest publication

- `BENCHMARKS.md` + `docs/accuracy.md`: add the real-world track section; replace the
  "real-code precision: not benchmarked" caveat with the measured number and per-class
  deltas; keep the "lower bound / label coverage" caveats — honesty is the feature.
- CI: real-world public tier + regression corpus as non-regression gates (seed tier stays
  local, loud-SKIP in CI).
- House-style docs: `NEXT_v110.md`, `TASK_MANIFEST_v110.md`; CHANGELOG entries per release
  playbook.

## 8. Success metrics / exit criteria

- Real-repo precision baseline exists, committed, reproducible (`benchmark compare` works).
- Measured precision improvement on the corpus after Phase B, with per-class evidence.
- Zero regression on the existing synthetic 1.000 gates and DAST baselines.
- Every Phase C rule ships with both `vulnerable` and `safe` corpus cases.
- `fendix verify` resolves correlated + active-probe findings (exit 0/1, not 2).

## 9. Testing

- Go: unit tests for label matching (±3 tolerance, path normalization, unknown handling),
  target loud-SKIP behavior, per-class aggregation; golden-file test for the triage report.
- Python: corpus cases per fix (`python/benchmark/corpus.json` + `run_benchmark.py` gate).
- End-to-end: `fendix benchmark run --target realworld` against a fixture mini-repo committed
  under `go/internal/benchmark/targets/testdata/`.

## 10. Risks

| Risk | Mitigation |
| --- | --- |
| Label anchors drift when corpus repos are re-pinned | pinned SHAs; labels versioned with the pin; ±3-line tolerance |
| Seed repos unavailable on other machines/CI | loud-SKIP, never silently green; public tier carries CI |
| B2 dominance fix surfaces new findings on real repos (was over-suppressing) | expected; they enter the harness as `unknown` → triage → label; recall gain is the point |
| B3 de-escalation hides real vulns in test code | INFO not IGNORE; config flag to disable; decision reasons state the rule |
| C2 env/config sources re-introduce FP-4-style noise | narrow scope + mandatory negative corpus cases before merge |
